## Regras duras (não violar)
- PROIBIDO: marcar artefato como `approved`/`accepted` ou promover ADR/baseline por inferência — decisões Classe C exigem aprovação humana explícita; aceite de valor é do PO; execução ≠ aceite. Anti-pattern: ver a suíte verde e registrar o incremento como `accepted`/`approved` sem DEC Classe C (ex.: "F-ÚNICO-1 done ⇒ valor aceito"). Recuperação: reverter o status para não aprovado, registrar a correção como nova entrada/adendo no log (nunca reescrever entradas) e escalar a decisão ao humano (Classe C) antes de qualquer promoção.
- PROIBIDO: inferir aprovação a partir de status de execução — a semântica de estados é distinta e não intercambiável: execução `done/blocked/partial` ≠ operacional `completed` ≠ valor `approved` (PO). Anti-pattern: tratar `done` no resumo de subagente como `completed` no board ou como `approved` de valor. Recuperação: reclassificar o estado na camada correta, anexar a evidência exigida por cada camada e submeter a decisão de valor ao PO (Classe C).
- OBRIGATÓRIO: gates de qualidade exigem baseline e evidência declarada — regra vigente é "no new errors" sobre a baseline declarada; thresholds (ex.: cobertura) lidos do `pyproject.toml` do projeto-alvo, nunca hardcodados em prosa. Anti-pattern: escrever "cobertura ≥ 80%" em prosa ou relaxar o gate para fazer a validação passar. Recuperação: ler o `fail_under` real do `pyproject.toml` do projeto-alvo, reverter o relaxamento e reexecutar a validação com o threshold declarado.
- PROIBIDO: assumir board/issue tracker externo existente — `docs/` é a trilha vigente (DEC-006(vi)); adoção de ferramenta externa (GitHub Issues/Projects) para escala pende de decisão Classe C (CR-010-C, DEC-027). Anti-pattern: citar "issue #123" ou abrir item em GitHub Projects como fonte de tracking sem DEC Classe C. Recuperação: rastrear somente em `docs/`, registrar a necessidade/lacuna e submeter a adoção a decisão Classe C antes de usá-la.
- OBRIGATÓRIO: todo status de execução documentado referencia artefato/evidência — sem evidência, não há `done`. Anti-pattern: marcar `done` no resumo/índice sem caminho de artefato, hash, commit ou output de gate. Recuperação: anexar a evidência faltante (caminho/URI/hash/commit) ou reclassificar o status para `partial`/`blocked` com bloqueios e próxima ação explícitos.
- OBRIGATÓRIO: conflito entre documentos deste repo ⇒ registrar como `[LACUNA]` e escalar — não há fonte executável para desempate; nunca "resolver" silenciosamente. Anti-pattern: eleger um dos documentos divergentes como "certo" e editar o outro para "ficar consistente" sem decisão registrada. Recuperação: manter ambos intactos, registrar `[LACUNA]` citando os dois lados e escalar ao Mantenedor (Classe C) para desempate.
